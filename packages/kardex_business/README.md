# kardex_business

Pure Dart package (no Flutter dependency) acting as the business layer and client SDK for the **Kardex Server** REST backend (`kardex-server`). Exposes **37 repositories** covering all operations for the inventory, sales, purchasing, finance, and administration management system.

## Requirements & Installation

- **Dart SDK**: `^3.11.0`
- **Main dependencies**: `http`, `dio`, `dio_cache_interceptor`, `hive`, `dart_jsonwebtoken`

Add to the consuming project's `pubspec.yaml`:

```yaml
dependencies:
  kardex_business:
    path: packages/kardex_business
```

---

## Configuration & Initialization

Before using any repository, the global client must be initialized by providing a concrete implementation of `KardexClientConfig`.

### KardexClientConfig

Abstract class that the consuming project must implement:

```dart
abstract class KardexClientConfig {
  String get baseUrl;          // Server base URL (e.g. "http://localhost:8000")
  String? get practiceUrl;     // Practice URL (optional, overrides baseUrl if set)
  String? get authToken;       // JWT authentication token
  String? get servinNickname;  // Servin licensing alias (optional)
  String? get branchId;        // Active branch ID (optional)
}
```

### KardexClient

Singleton that holds the global configuration:

```dart
KardexClient.initialize(MyConfig(
  baseUrl: 'http://localhost:8000',
));
```

Once initialized, any repository can be instantiated directly:

```dart
final productsRepo = ProductsRepository();
final clientsRepo = ClientsRepository();
```

## How It Works

### URL Construction

URLs are built using the pattern:

```
{baseUrl}/api/v{version}/{entity}?{queryParams}
```

- `baseUrl` comes from `KardexClientConfig.baseUrl`.
- If `practiceUrl` is set, it overrides `baseUrl`.
- Default API version is `1`.
- Supports both `http` and `https`.

Concrete example:

```
GET http://localhost:8000/api/v1/products?offset=0&limit=50
POST http://localhost:8000/api/v1/products
GET http://localhost:8000/api/v1/products/abc123
PATCH http://localhost:8000/api/v1/products/abc123
DELETE http://localhost:8000/api/v1/products/abc123
```

### Authentication & Headers

Every authenticated request includes the following headers generated by `HttpTools.generateAuthHeaders()`:

```
Authorization: Bearer <jwt_token>
X-Agent: Neptuno
X-Servin: <servinNickname>   (if configured)
X-Branch: <branchId>         (if configured)
```

### Token Lifecycle

`TokenManager` is an in-memory singleton that:

- Stores the JWT after login (`/auths/login`).
- Decodes the token using `dart_jsonwebtoken` to check expiration.
- `isTokenGotExpired()` returns `true` if the token will expire within **1 hour** (3600-second safety buffer).
- The consuming project is responsible for calling `/auths/refresh-token` when the token is close to expiration.

### HTTP Clients

The package offers two mixins depending on caching needs:

| Mixin | Base package | Cache | Typical use |
|---|---|---|---|
| `HttpService` | `package:http` | No | Standard CRUD (most DataSources) |
| `DioHttpService` | `dio` + `dio_cache_interceptor` + `hive` | Yes, disk via Hive | Frequent read queries (admin panels, integrations, transfers) |

## General Architecture

The package follows a strict **Onion (Clean Architecture)** pattern:

```
┌─────────────────────────────────────────────────────────────┐
│ Presentation Layer (Flutter App)                            │
│  → Cubits / BLoCs                                           │
├─────────────────────────────────────────────────────────────┤
│ Domain Layer (kardex_business)                              │
│  ┌───────────────────────────────────────────────────────┐  │
│  │ Repositories                                          │  │
│  │  → Parse JSON into typed models                       │  │
│  │  → Maintain in-memory cache (optional)                │  │
│  │  → Emit reactive events (optional)                    │  │
│  ├───────────────────────────────────────────────────────┤  │
│  │ Data Sources                                          │  │
│  │  → Raw HTTP calls                                     │  │
│  │  → Return Map<String, dynamic>                        │  │
│  └───────────────────────────────────────────────────────┘  │
├─────────────────────────────────────────────────────────────┤
│ Infrastructure Layer                                        │
│  → HttpService / DioHttpService                             │
│  → TokenManager / HiveService                               │
└─────────────────────────────────────────────────────────────┘
```

**Rule**: the presentation layer **never** consumes DataSources directly; it always does so through Repositories.

Each repository follows the standard CRUD pattern where applicable:

| Operation | HTTP Method | Path |
|---|---|---|
| Create | `POST` | `/{entity}` |
| List | `GET` | `/{entity}` |
| Get by ID | `GET` | `/{entity}/{id}` |
| Update | `PATCH` | `/{entity}/{id}` |
| Delete | `DELETE` | `/{entity}/{id}` |

### 6.1 HttpTools

```dart
// Build URI
Uri uri = HttpTools.generateUri(

  queryParams: {'offset': '0', 'limit': '50'},
);

// Generate auth headers
Map<String, String> headers = HttpTools.generateAuthHeaders();
```

| Static Method | Description |
|---|---|
| `generateUri(String path, {Map<String, dynamic>? queryParams, int version = 1})` | Builds the full URI: `{baseUrl}/api/v{version}{path}?{params}` |
| `generateAuthHeaders()` | Returns `Authorization`, `X-Agent`, optionally `X-Servin` and `X-Branch` headers |

### 6.2 TokenManager

| Method | Description |

| Method | HTTP Method | Description |
|---|---|---|

| `deleteQuery(String path, {Map<String, dynamic>? queryParams})` | `DELETE` | Deletion |
| `multipartQuery(String path, {required String method, Map<String, dynamic>? fields, List<MultipartFile>? files})` | Multipart | File upload |

| Method | Description |
|---|---|

### 6.5 HiveService

Mixin for opening/closing Hive boxes (local key-value storage).

| Method | Description |
|---|---|

### 6.6 ReactiveRepository

Mixin that adds reactive capability to a repository. Emits events via a `Stream` when entities are created, updated, or deleted.

```dart
enum RepoOperation { created, updated, deleted }

class RepoEvent<T> {
  final RepoOperation operation;
  final T model;
}
```

No repositories in the package currently use this mixin, but it is available for the consuming project to apply when reactivity is needed.

## 7. HTTP Exceptions

The package defines a sealed exception hierarchy in `http_exceptions.dart`:

| Exception | HTTP Code | Description |
|---|---|---|
| `NoInternetException` | N/A | No internet connection |
| `ServerException` | 5xx | Internal server error |
| `BadRequestException` | 400 | Invalid request data |
| `UnauthorizedException` | 401 | Expired token or invalid credentials |
| `ForbiddenException` | 403 | No permission for the resource |
| `InternalRequestException` | Other 4xx | Other client errors |

All extend `HttpException`, which includes the `statusCode` and server `message`.

```dart
class ListResponse<T> {
```

## 10. Usage Example

```dart
import 'package:kardex_business/kardex_business.dart';

void main() async {
  // 1. Initialize the client
  KardexClient.initialize(MyConfig(
    baseUrl: 'http://localhost:8000',
    branchId: 'branch-001',
  ));

  // 2. Authenticate
  final authRepo = AuthRepository();
  final loginResponse = await authRepo.login('admin', 'password123');

  // 3. Query products
  final productsRepo = ProductsRepository();
  final products = await productsRepo.getPaginatedProducts(0);

  // 4. Get inventory by branch
  final inventoryRepo = InventoriesRepository();
  final inventory = await inventoryRepo.getAllInventories('branch-001');

  // 5. Create an order
  final ordersRepo = OrdersRepository();
  final newOrder = await ordersRepo.createOrder(CreateOrder(
    clientId: 'client-123',
    products: [...],
  ));

  // 6. Convert order to invoice
  final invoiceResponse = await ordersRepo.convertOrderToInvoice(newOrder.id);

  // 7. Query dashboard
  final dashboardRepo = AdminPanelRepository();
  final charts = await dashboardRepo.getAdminCharts(
    endDate: DateTime.now().millisecondsSinceEpoch,
  );

  // 8. Check expirations
  final expRepo = ExpirationLogsRepository();
  final hasExpired = await expRepo.hasExpiration('branch-001');

  // 9. Get financial report
  final reportsRepo = ReportsRepository();
  final totals = await reportsRepo.getTotalResultsByDateRange(
    TotalsQueryParams(startDate: '2024-01-01', endDate: '2024-01-31'),
  );

  // 10. Logout
  TokenManager().removeToken();
}
```
